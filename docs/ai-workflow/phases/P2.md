# P2: Staged Celery workers → Redis vector + text index ⭐ resume checkpoint
Mode: plan first. Implement only after I approve.

## Goal
Process every UPLOADED document through parse → chunk → embed → index using idempotent Celery tasks on separate queues. The result is chunks stored in MySQL plus a searchable Redis 8.4 index (vector + text) built from them.

## Constraints
- **Outbox relay:** use `SELECT ... FOR UPDATE SKIP LOCKED`, then enqueue `parse(doc_id, version)`.
- **Queues:** `parse` (CPU, concurrency 2), `chunk`, `embed` (concurrency capped for the OpenAI rate limit), `index`. Chain the stages by enqueueing the next one at the end of each task. Do not use one giant chain object.
- **Parse:** extract text per page with page numbers. Run Tesseract OCR only on pages that have no text layer. Raise `PermanentError` for corrupt or encrypted files.
- **Chunk:** about 500 tokens with 50 tokens of overlap, respecting headings and paragraphs, keeping `page_from`/`page_to`, and upserting on `UNIQUE(document_id, version, ord)`.
- **Embed:** batches of 100 calls to the embedding model. Mark `embedding_done` only for the rows that succeeded.
- **Index:** one hash per chunk at `chunk:{tenant}:{chunkId}`, with fields `tenant` TAG, `doc_id` TAG, `text` TEXT, `page` NUMERIC, `embedding` VECTOR. Create the index at startup if it doesn't exist (HNSW, FLOAT32, COSINE).
- Every task follows the idempotency and acks rules in CLAUDE.md, and updates `document_stages` and the document status.
- Batch status is DONE or PARTIAL, derived from its documents.
- `reindex` CLI: rebuild a tenant's Redis hashes from MySQL chunks.

## Deliverables
- The relay, 4 task modules, index bootstrap, the `reindex` CLI, and a progress endpoint showing the per-stage status
- Update the upload UI to show live per-document stage progress (polling every 2 s is fine)
- Tests:
  - chunker page mapping
  - a task run twice gives the same chunk count (idempotency)
  - a permanent error ends FAILED with no retries
  - integration: 5 sample PDFs end INDEXED and `FT.SEARCH` finds a known phrase

## Done when
- Uploading 5 PDFs (one of them scanned) ends with all 5 INDEXED. Chunk counts match between MySQL and Redis.
- Flushing Redis and then running `reindex` restores an identical index.
