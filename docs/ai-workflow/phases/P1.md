# P1: Upload pipeline (presigned S3 + batch/document state)
Mode: plan first. Implement only after I approve.

## Goal
A tenant creates a batch, gets presigned upload URLs, uploads files directly to S3 (MinIO locally), then confirms each upload. The API verifies the object and moves the document to UPLOADED, recording an outbox event in the same transaction.

## Read these files
- `CLAUDE.md`
- `docs/specs.md`, section 5 (tables `tenants`, `batches`, `documents`, `outbox_events`; the document state machine), section 6 (`/batches`, `/documents/:id/complete`, GET routes) and section 7 (flow 1)

## Constraints
- docker-compose: mysql, redis, flyway, minio (+ bucket init), api, caddy.
- Migration `V1__init.sql` creates **all** the tables in section 5, so later phases don't need schema churn.
- Quota checks: tenant max file size and max files per batch. Allowed MIME types: PDF and DOCX.
- Object keys look like `tenant/{tenantId}/batch/{batchId}/{documentId}/{safeFilename}`. Presigned PUT URLs expire after 15 min.
- `complete` runs `HEAD` on the object, checks size and SHA-256 (sent by the client as metadata) and checks the tenant prefix. It then runs the conditional update `WHERE status='CREATED'` plus the outbox insert in one transaction. A duplicate `complete` call is a no-op that returns 200.
- Auth: a static tenant API key header for now (`X-Tenant-Key`).

## Deliverables
- The Flask app factory, SQLAlchemy models, the routes above, the S3 service, and the `seed-tenant` CLI
- A minimal React upload page: pick files → compute SHA-256 in the browser → PUT to the presigned URL → call `complete` → show the status table
- Tests: quota rejection, a duplicate `complete`, a tenant prefix mismatch rejected, and a happy path against MinIO (integration)

## Done when
- Uploading 5 PDFs from the UI ends with 5 documents in UPLOADED and 5 outbox rows.
- A file that is too large is rejected before the upload. A duplicate `complete` call doesn't create a second outbox row.
- `pytest -q` and `pytest -m integration` are green.

## Out of scope
Celery workers (P2), retrieval (P4), the chat UI (P5).
