# P3: Reliability: retries, DLQ, replay, cancel, chaos tests
Mode: plan first. Implement only after I approve.

## Goal
Make the pipeline survive real failures:
- transient errors retry with backoff and jitter
- permanent errors fail fast
- exhausted jobs land in a DLQ and can be replayed as a new version
- batches can be cancelled
- a worker killed mid-task never produces duplicate output

## Read these files
- `CLAUDE.md`
- `docs/specs.md`, section 5 ("Celery design", `dead_letters`, the state machine) and section 8 (failure table)
- `apps/worker/tasks/*`

## Constraints
- **Error types:** a `TransientError` (timeouts, 429, S3 5xx, connection errors) and a `PermanentError`. Use `autoretry_for=(TransientError,)`, `retry_backoff=True`, `retry_backoff_max=300`, `retry_jitter=True`, `max_retries=5`. Honour `Retry-After` from OpenAI when present.
- **On final failure:** insert `dead_letters`, set the stage and document to FAILED, and recompute the batch status.
- **`POST /documents/:id/replay`:** bump `processing_version`, enqueue `parse` for the new version, and mark the DLQ row as replayed. The old version's chunks stay until the new version is INDEXED, then the old Redis keys are deleted (an atomic swap).
- **`POST /batches/:id/cancel`:** set CANCEL_REQUESTED. Tasks check it at the start and don't enqueue the next stage. The document ends CANCELLED.
- **Chaos harness:** a script that starts a batch of 50 docs, kills the embed worker container mid-run (`docker kill`), restarts it, then checks the invariants (no duplicate chunks, every doc ends INDEXED or FAILED, Redis count = MySQL count).

## Deliverables
- Error classes and task decorators, the DLQ, the replay and cancel endpoints, the chaos script `scripts/chaos_embed.py`, and DLQ + replay buttons in the UI
- Tests: a mocked 429 then success → retried; a permanent error → no retry; the replay version swap; a cancel mid-pipeline

## Done when
- The chaos script passes 3 runs in a row and its output is saved to `docs/results.md`.
- A mocked failure that exhausts retries appears in the DLQ, and replaying it ends INDEXED as version 2.

## Out of scope
Retrieval quality (P4), autoscaling.
